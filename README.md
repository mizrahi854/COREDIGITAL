# BUBER — רשת חברתית ליופי שמובילה לקביעת תור

**רואים. בוחרים. קובעים.** לקוחות מגלים עבודות אמיתיות בסרטונים אנכיים, מגיעים לעסק שעשה אותן, רואים שירות, מחיר וזמינות — וקובעים תור. עסקים מקבלים פרופיל ציבורי, יומן, ניהול שירותים וצוות, העלאת רילס ונתונים על איזה תוכן מביא הזמנות.

> כל העסקים, האנשים, הביקורות והמדיה ב־seed הם **לדוגמה** ומסומנים ככאלה בממשק. הסרטונים והתמונות הם איורים מופשטים שנוצרו בקוד (`npm run media:generate`), לא עבודות של עסקים אמיתיים.

---

## סטאק

| שכבה | בחירה |
| --- | --- |
| אפליקציה | Next.js 16 (App Router, React 19, TypeScript), Tailwind CSS 4, RTL מלא, Heebo |
| שרת | Route Handlers + שכבת שירות ב־`src/server` |
| מסד נתונים | PostgreSQL 14+ דרך Prisma 6 (מיגרציות ב־`prisma/migrations`) |
| אימות | סשנים בבסיס הנתונים (cookie `httpOnly`, `SameSite=Lax`), bcrypt |
| מדיה | אדפטר אחסון מקומי (`MEDIA_ROOT`) + ffmpeg לעיבוד (MP4/H.264 + WebM/VP9 + תמונה ממוזערת) |
| עבודות רקע | תור עבודות ב־Postgres (`FOR UPDATE SKIP LOCKED`) — עיבוד רילס ומשלוח הודעות |
| בדיקות | Vitest (אינטגרציה מול Postgres) + Playwright (E2E מול build פרודקשן) |

## התקנה והרצה מקומית

דרישות: Node 20.9+, PostgreSQL 14+ (עם `btree_gist` — מגיע עם Postgres הסטנדרטי), ffmpeg/ffprobe ב־PATH.

```bash
# 1. תלויות
npm install

# 2. מסד נתונים (דוגמה עם משתמש מקומי)
createuser -d buber --pwprompt          # סיסמה: buber
createdb -O buber buber

# 3. משתני סביבה
cp .env.example .env                    # ערכו DATABASE_URL אם צריך

# 4. מיגרציות + נתוני דמו (ה־seed מוחק את כל הנתונים בבסיס שהוגדר!)
npm run db:migrate
npm run db:seed

# 5. הרצה
npm run dev                             # http://localhost:3000
```

המדיה לדוגמה כבר נמצאת ב־`sample-media/` (ה־seed מעתיק אותה ל־`MEDIA_ROOT`). ליצירה מחדש: `npm run media:generate` (דורש Chromium של Playwright ו־ffmpeg).

### פרודקשן מקומי

```bash
npm run build
RUN_WORKER_IN_APP=false npm start       # שרת web
npm run worker                          # תהליך worker נפרד (עיבוד וידאו, הודעות)
```

## בדיקת כל תפקיד

ב־`/login` (במצב פיתוח בלבד, `DEV_LOGIN_ENABLED=true`) יש כפתורי כניסה מהירה. הסיסמה לכל חשבונות הדמו: **`buber1234`**.

| תפקיד | אימייל | מה לבדוק |
| --- | --- | --- |
| לקוחה | `customer@buber.dev` | פיד → ״קביעת תור״ מסרטון → אישור; שמורים ואוספים; ״התורים שלי״ — כולל בקשה בתיאום מחיר שמחכה לעסק |
| לקוח נוסף | `customer2@buber.dev` | לא רואה תורים של דנה (404) |
| בעלת עסק | `owner@buber.dev` | `/biz`: נתונים, יומן יום/שבוע, תור ידני, שירותים, צוות ושעות, רילס, פרופיל; שליחת הצעה לבקשה הממתינה |
| צוות | `staff@buber.dev` | רואה רק את היומן והתורים שלה; אין גישה לשירותים/פרופיל |
| בעל עסק אחר | `owner-barber@buber.dev` | לא יכול לגעת בתורים של אלמנד (403) |
| מנהלת מערכת | `admin@buber.dev` | `/admin`: אישור עסק ממתין, דיווחים, הסתרת תוכן, בעיות בתורים, יומן פעולות, יומן משלוחים |

חשבון אחד יכול להיות גם לקוח וגם בעלים/צוות של עסק — המעבר בפרופיל (״מצבי חשבון״) או ב״מעבר למצב לקוח״ בדשבורד.

## בדיקות

```bash
npm run typecheck
npm run lint
npm test            # Vitest — דורש מסד buber_test (createdb -O buber buber_test)
npm run build
npm run test:e2e    # Playwright — דורש מסד buber_e2e; מריץ build פרודקשן על פורט 3100 עם seed טרי
```

מה מכוסה:

- **זמינות** — שעות עבודה, משך + זמן הכנה, הפסקות, חופשות, תורים קיימים, התאמת צוות לשירות, זמן מינימלי מראש, ומעבר שעון קיץ/חורף ב־Asia/Jerusalem (מרץ ואוקטובר 2026).
- **שלמות הזמנות** — 8 בקשות מקבילות לאותו משבצת: בדיוק אחת מצליחה; חפיפה חלקית נדחית; ״כל מי שפנוי״ מתחלק בין אנשי צוות; ה־DB עצמו דוחה חפיפה (exclusion constraint); הגשה חוזרת עם אותו מפתח אידמפוטנטיות מחזירה את אותו תור.
- **ביטול** משחרר זמינות; **שינוי מועד** אטומי — אם המועד החדש תפוס, התור המקורי לא נפגע; **עריכת שירות/מדיניות** לא משנה תורים קיימים.
- **שירות בתיאום** — בקשה לא תופסת משבצת; הצעה → אישור לקוח עם בדיקה חוזרת.
- **הרשאות** — לקוח/עסק/צוות/מנהל, מקור בקשה (CSRF), כניסת פיתוח כבויה בפרודקשן.
- **מדיה** — העלאה שבורה מסתיימת ב־FAILED ולא מופיעה בפיד; קובץ שאינו וידאו נדחה לפני יצירת רשומה; עיבוד תקין מפרסם.
- **E2E** — המסע המלא (פיד → עסק → הזמנה → העסק רואה → אישור ללקוח), חיפוש ומסננים שנשמרים, שמורים ואוספים, ניגון רק של הסרטון הפעיל, prefers-reduced-motion, ובדיקת גלילה אופקית ב־RTL במובייל ובדסקטופ.

## איך זה בנוי (נקודות חשובות)

- **מניעת הזמנה כפולה** (`src/server/booking.ts`): הזמינות מחושבת מחדש בשרת בתוך טרנזקציה; נעילת advisory לכל איש צוות; ו־`EXCLUDE USING gist` על `(staffId, [startsAt, blockEndsAt))` לתורים מאושרים/שהושלמו (`prisma/migrations/*_init`). `blockEndsAt` כולל את זמן ההכנה.
- **הסכם התור**: שם השירות, מחיר, משך, זמן הכנה ומדיניות ביטול נשמרים על התור עצמו.
- **זמן**: שעות עבודה נשמרות כדקות משעון־קיר מקומי ומתורגמות עם Luxon באזור Asia/Jerusalem, כך ש־09:00 נשאר 09:00 גם במעבר שעון.
- **סדר הפיד** (`src/server/feed.ts`): שקוף — טריות (מחצית חיים 7 ימים) + עוקב/ת (2) + אזור (1.5) + תחום עניין (1). הסיבה מוצגת על כל סרטון.
- **ייחוס**: לחיצה על ״קביעת תור״ ברילס נרשמת כ־BOOKING_START, והתור שומר `sourceReelId`; בדשבורד יש טבלת רילס → תורים. ״ערך צפוי״ (מחירים שסוכמו) מוצג בנפרד מ״תשלומים שנרשמו בפועל״.
- **הודעות** (`src/server/notifications.ts`): אישור ותזכורת 24 שעות נשמרים כרשומות באותה טרנזקציה עם התור, ונשלחים ע״י ה־worker כשמגיע הזמן. בלי ספק מוגדר הן מסומנות **LOGGED — לא נשלחו בפועל** ומוצגות ביומן המשלוחים במנהל.
- **תשלומים** (`src/server/payments.ts`): גרסה 1 = תשלום בעסק; העסק רושם סכום ששולם בסיום טיפול. ממשק `PaymentProvider` מוכן למקדמות/החזרים. אין שמירת פרטי כרטיס.
- **אבטחה**: הרשאות נאכפות בכל route בשרת (`src/server/access.ts`); בדיקת Origin לבקשות משנות (`src/proxy.ts`); rate limiting מבוסס Postgres; בדיקת סוג קובץ לפי magic bytes, מגבלות גודל/אורך, הסרת מטא־דאטה מתמונות; הקבצים המקוריים לא מוגשים.

## מה צריך לפרודקשן

| צורך | מצב היום | מה לחבר |
| --- | --- | --- |
| אחסון מדיה | דיסק מקומי (`MEDIA_ROOT`) | S3 / R2 / GCS — מימוש של `MediaStorage` ב־`src/server/storage.ts` + CDN |
| אימייל | יומן פיתוח (LOGGED) | ספק כמו Resend/SendGrid/SMTP — `providerFor()` ב־`notifications.ts` |
| SMS | יומן פיתוח | ספק SMS ישראלי |
| תשלומים / מקדמות | תשלום בעסק | סולק עם checkout מאובטח — `PaymentProvider` |
| עבודות רקע | worker יחיד/בתוך השרת | `npm run worker` כתהליך נפרד (אפשר כמה במקביל) |
| Rate limiting | Postgres | Redis לעומס גבוה |
| מסד נתונים | Postgres מקומי | Postgres מנוהל עם גיבויים |
| דומיין + HTTPS | — | חובה (עוגיות `Secure` בפרודקשן) |

## מגבלות ידועות

- התוכן לדוגמה הוא איורים מופשטים, לא צילומי עבודות אמיתיות.
- אין עדיין שליחת אימייל/SMS אמיתית, תשלום מקוון, אימות טלפון/אימייל או איפוס סיסמה.
- המרחק בחיפוש מחושב רק כשיש קואורדינטות לשני הצדדים; בבחירת עיר ידנית הוא משוער ממרכז העיר ומסומן ב־״~״. אין מפה.
- איש צוות מוגדר עם טווח עבודה והפסקה אחת ליום בממשק (המודל תומך ביותר).
- סימון ״הושלם״ ו״לא הגיע/ה״ ידני ע״י העסק.
- נדחו בכוונה (לפי האפיון): תגובות ציבוריות, רילס של לקוחות, AI/חיפוש לפי תמונה, צוותים ניידים, מטבעות/מנויים/מוצרים, מפות מורכבות וסנכרון יומנים חיצוניים.
